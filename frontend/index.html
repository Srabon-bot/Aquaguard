Regional forecast models

Three independent models, each trained on real historical flood data for 30 Bangladesh river gauge stations. Each calls its own local service — start them first (see frontend/README.md).

Runs all 3 models together and builds the pipeline summary below — or run one at a time using the buttons in each card.

Flood risk classifier

Flood / no-flood risk at 24h, 48h, and 72h ahead.

River discharge forecaster

Predicted river discharge (m³/s) at 24h, 48h, and 72h ahead.

Flood susceptibility

How flood-prone this ground is by nature (terrain, not weather) — static, no forecast horizon.

Pipeline summary

All 3 models feed into this: the discharge forecaster's own prediction is a live input to the flood-risk classifier, and this panel states what each model actually found in plain terms — not a single pre-judged verdict — so you can weigh the facts yourself. Run the flood risk and susceptibility models above for this to appear.

Suggested additions

Not built yet — ideas for where this dashboard/project could go next.

  • Alert thresholds & notifications. Push/SMS/WhatsApp alert when a sensor crosses a safe-range bound or the flood model crosses "high" — many rural farmers don't have always-on smartphone data, so SMS (via a gateway like Twilio or a local aggregator) reaches further than a push notification.
  • Historical trend charts. Once Firebase is populated for real, line charts per sensor (last 24h/7d) sit naturally next to the current stat tiles — the dataviz groundwork in this page's CSS already supports it.
  • Combined-condition trigger for the pumps. Instead of the ultrasonic sensor or the flood model acting alone, trigger the water-exchange motors only when both agree conditions warrant it — discussed in MODEL_BUILD_PLAN.md but not built.
  • Dissolved oxygen sensor. The single most consistently-cited critical water-quality parameter in aquaculture research that this sensor suite currently lacks — flagged in PROJECT_FEATURE_IDEAS.md, not yet acted on.
  • Station-relative discharge anomaly score. The discharge forecaster currently returns a raw m³/s number that isn't directly comparable across rivers of very different size — converting to a percentile/z-score against that station's own history would make the number meaningful at a glance on this dashboard.
  • Multi-tank / multi-pond support. Right now the layout assumes one tank — a real deployment (or a more ambitious capstone demo) might manage several, each with its own card.
  • Exportable report. A "download PDF" of the current dashboard snapshot — sensor readings, weather, both model outputs — useful for a capstone defense appendix or a farmer's own records.
